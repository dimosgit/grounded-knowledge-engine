# Stitch prompt: quiet area-first Cockpit

Design a production web application flow for the Operator Cockpit using the
attached `design.md` and `sample-focus-data.json`.

Create these responsive screens in both **Slick Minimalist** and **Warm Paper**:

1. An area chooser for Delivery, Product, and Learning.
2. A focused area view with one current item and up to two next items.
3. An opened Explore surface with routes to related projects, documents,
   decisions, attention, planning, and review.
4. Empty, loading, unavailable, and read-only states.

Keep the default view calm. Do not add dashboards, charts, activity feeds,
timers, fabricated metrics, assistant avatars, or permanent alert panels.
Supporting information must remain easy to find through clear secondary
actions.

Use realistic fictional data only. Do not introduce organization names, real
people, customer details, credentials, private endpoints, or local filesystem
paths. Keep icons, metadata, dividers, and meaningful state detail so the result
looks like a usable application rather than a wireframe.

Preserve the same information architecture and component structure across both
themes. Include desktop, tablet, and 390 px mobile layouts. Show visible keyboard
focus, readable status colors, reduced-motion-friendly transitions, and menus
that remain inside the viewport.
